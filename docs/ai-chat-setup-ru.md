# Как включить ИИ-гараж в DriveCare

Проверено по коду приложения и официальной документации Firebase 25 октября 2026.

Без локального `app/google-services.json` приложение показывает, что ИИ недоступен.
Сам экран и клиент запросов уже реализованы. Если Firebase уже подключён,
соответствующие шаги повторять не требуется.
Чтобы начать получать ответы, нужно один раз подключить свой Firebase-проект.
Регистрация в ChatGPT, ключ OpenAI и покупка DriveCare Pro для этого не нужны.

## 1. Создать проект Firebase

Откройте [Firebase Console](https://console.firebase.google.com/), войдите в Google
и создайте проект, например `DriveCare`. Можно использовать отдельный проект для
разработки. Google Analytics для ИИ не обязателен; приложение его не использует.

В проекте откройте настройки → **Project settings → General → Your apps**,
добавьте Android-приложение. Точное имя пакета текущей сборки:

```text
com.example.drivecare
```

Имя проекта и отображаемое название приложения могут быть любыми; пакет должен
совпадать с `applicationId` в `app/build.gradle.kts`. Если меняете пакет перед
публикацией, зарегистрируйте соответствующее Android-приложение заново.

## 2. Добавить сертификаты подписи

В терминале Android Studio, из корня DriveCare, выполните:

```sh
./gradlew :app:signingReport
```

В секции `Variant: debug` скопируйте SHA-1 и SHA-256. Добавьте их к Android-приложению
в Firebase: **Project settings → Your apps → SHA certificate fingerprints**.
Это отпечатки публичного сертификата, не пароль и не приватный ключ.
Для выпуска потребуются отдельные отпечатки реальной release/Play App Signing
подписи; debug-сертификат их не заменяет.

## 3. Сохранить конфигурацию в проект

Скачайте `google-services.json` для зарегистрированного Android-приложения.
Положите именно сюда:

```text
DriveCare/app/google-services.json
```

Не в корень репозитория и не в `assets`. Если браузер добавил `(1)` к имени,
переименуйте файл. Не редактируйте его содержимое вручную. Файл уже исключён
из Git. Google Services Gradle plugin включится автоматически при его наличии.
Все необходимые Firebase-зависимости уже подключены — копировать зависимости
из примеров документации или менять версии не нужно.

## 4. Включить Firebase AI Logic

В Firebase Console откройте **AI Services → AI Logic → Get started**.
Пройдите мастер настройки и выберите **Gemini Developer API**. Именно этот
провайдер используется в коде (`GenerativeBackend.googleAI()`). Разрешите мастеру
включить требуемые API и закончите настройку ресурсов.

Не вставляйте сырой Gemini API key в Kotlin, `BuildConfig`, `local.properties`
или приложение. Клиент использует конфигурацию Firebase и Firebase AI Logic.
Отдельный backend, Firebase Authentication, Firestore и RevenueCat для текущего
ИИ-функционала не требуются. Процесс описан в
[официальном руководстве](https://firebase.google.com/docs/ai-logic/get-started?platform=android).

В приложении разрешена модель **`gemini-3.5-flash-lite`**. Она присутствует в
[официальном списке моделей](https://firebase.google.com/docs/ai-logic/models?api=dev).
Не заменяйте её произвольным именем из примера: другое имя Remote Config будет
отклонено текущим кодом. Поддержка другой модели потребует отдельной проверки
и изменения разрешённого списка в приложении.

## 5. Выбрать условия использования и лимиты

Для первого запуска можно использовать доступный вашему проекту бесплатный
уровень Gemini Developer API без привязки Cloud Billing. Доступность модели,
региона и квоты нужно проверить в консоли. Это не обещание безлимитных запросов.
После подключения Cloud Billing использование Gemini Developer API переходит
на оплату по использованию; не подключайте оплату, предполагая, что всё останется
в бесплатной квоте. См. [текущие условия оплаты](https://firebase.google.com/docs/ai-logic/pricing).

Перед публичным выпуском задайте подходящие квоты, ограничения запросов,
наблюдение за использованием и доступные средства контроля расходов на стороне
проекта. Уведомления о бюджете сами по себе не гарантируют остановку расходов.
Также прочитайте [условия обработки данных Gemini](https://ai.google.dev/gemini-api/terms):
условия бесплатного и оплачиваемого использования могут различаться.

## 6. Пересобрать debug и зарегистрировать App Check debug token

Синхронизируйте Gradle в Android Studio и запустите вариант **debug** на уже
имеющемся эмуляторе или своём устройстве. Через терминал сборка выглядит так:

```sh
./gradlew :app:assembleDebug
```

Устанавливайте свежий `app/build/outputs/apk/debug/app-debug.apk` поверх предыдущей
debug-сборки с той же подписью. Удалять приложение и его записи не требуется.
В debug уже включён Debug App Check provider, в release — Play Integrity.

Откройте **Logcat** в Android Studio для нужного устройства. Найдите сообщения
по `DebugAppCheckProvider`. После инициализации/первого запроса SDK напечатает
сообщение о debug secret с токеном формата UUID. При необходимости откройте
ИИ-гараж, подтвердите согласие и отправьте вопрос, чтобы инициировать запрос.
Первый запрос до регистрации токена может закончиться ошибкой — это ожидаемо.

В Firebase Console откройте **Security → App Check → Apps**, найдите своё
Android-приложение → меню с тремя точками → **Manage debug tokens** → добавьте
токен из Logcat, задав понятную метку устройства. Не публикуйте токен, не
коммитьте его и не добавляйте в релиз. У другого устройства или после очистки
данных может появиться другой токен. См.
[официальные шаги для debug provider](https://firebase.google.com/docs/app-check/android/debug-provider).

В новых проектах мастер AI Logic может уже включить обязательную проверку
App Check. Проверьте состояние защиты AI Logic в консоли. Для локальной
разработки зарегистрируйте debug token, сохраняя проверку включённой.
После регистрации перезапустите приложение и повторите запрос. Если SDK
показывает временный backoff после предыдущих отказов, дождитесь разрешённого
повторного запроса. Не очищайте данные ради повторной попытки.

## 7. При необходимости настроить Remote Config

Для первого запуска создавать параметры вручную необязательно: значения по
умолчанию уже установлены приложением. Если хотите управлять ими удалённо,
в **Remote Config** добавьте и опубликуйте:

| Параметр | Тип | Значение |
| --- | --- | --- |
| `ai_enabled` | Boolean | `true` |
| `ai_model` | String | `gemini-3.5-flash-lite` |
| `ai_daily_allowance` | Number | `5` |

`false` в `ai_enabled` отключает новые обращения. Суточное значение ограничено
кодом диапазоном 0–10. После публикации Remote Config может обновиться не сразу:
SDK использует кеш и свой интервал загрузки. При ошибке загрузки остаются
доступны сохранённые/стандартные значения.

## 8. Отправить первый вопрос

1. Добавьте автомобиль и выберите его активным в гараже.
2. Укажите известные двигатель, поколение и коробку передач в дополнительных
   параметрах автомобиля — ответы будут учитывать эти сведения.
3. Откройте вкладку **ИИ-гараж**. Проверьте автомобиль в карточке контекста.
4. Выберите тему: слабые места, обслуживание, улучшения или вопрос по записям.
5. Напишите, например: «Что проверить перед дальней поездкой для моего авто?
   Укажи, каких данных не хватает, и не придумывай заводские интервалы».
6. По желанию включите добавление краткой сводки записей. По умолчанию она
   не должна быть обязательной для вопроса.
7. Нажмите «Отправить» и подтвердите согласие на передачу выбранного контекста
   облачному ИИ, если оно ещё не получено. После подтверждения приложение
   отправит этот вопрос автоматически.
8. Дождитесь ответа. Его можно сохранить как заметку или открыть черновик плана
   ТО, проверить поля и сохранить самостоятельно. ИИ сам записи не изменяет.

По умолчанию есть **5 успешных новых ответов в сутки на установку** и пауза
**30 секунд** между успешными запросами. Pro этот лимит не увеличивает. Это
локальная защита интерфейса, не платёжный лимит проекта и не строгий лимит
пользователя на нескольких устройствах. Ответы сохраняются локально и доступны
без интернета. Новый вопрос требует сети. Это помощник со структурированными
ответами и историей, а не полноценный чат с автоматической передачей всех
предыдущих сообщений в каждом запросе.

## 9. Если не заработало

| Симптом | Что проверить |
| --- | --- |
| «ИИ недоступен», кнопка отправки неактивна | В APK нет Firebase-конфигурации: проверьте путь и имя JSON, совпадение пакета, Gradle Sync и переустановку свежей debug-сборки. |
| Общая ошибка/403 после отправки | Настройка AI Logic завершена, API включены, App Check токен именно этого устройства зарегистрирован в правильном проекте; ограничения API key соответствуют Firebase AI Logic. Не публикуйте полный Logcat с токенами. |
| В debug работает, в release нет | Debug token для release не подходит. Проверьте Play Integrity, release/Play App Signing SHA-256 и способ установки. |
| Недоступность после изменения Remote Config | `ai_enabled=true`, имя модели точно `gemini-3.5-flash-lite`, лимит больше нуля; учтите кеш Remote Config. |
| Нет интернета/тайм-аут | Проверьте сеть устройства и доступность сервисов Google в регионе, повторите позже. |
| Лимит или 429 | Различайте локальные 5 ответов/30 секунд и серверные квоты проекта; проверьте использование в консоли. |
| Ответ не сохранился, предложено повторить | Приложение могло отклонить неверный формат/слишком большой ответ модели; это не успешный локальный ответ. Не ослабляйте валидацию ради обхода. |
| Ответу не хватает конкретики | Заполните точные характеристики автомобиля и задайте конкретный вопрос. Приложение не содержит заводскую ремонтную базу. |

## 10. Перед выпуском пользователям

В Firebase App Check зарегистрируйте production-провайдер **Play Integrity**
для Android и SHA-256 сертификата реальной подписи из Google Play Console →
App integrity → App signing. Проверьте связь Play Integrity с проектом,
доступность API и требования к verdict в соответствии с вашим распространением.
Код release-провайдера уже есть, но настройку консоли код выполнить не может.
Проверьте подписанный выпуск, установленный из внутреннего трека Google Play,
и валидные запросы в метриках App Check. Затем подтвердите enforcement AI Logic
и заданные квоты. Дополнительная replay protection — отдельная настройка,
требующая поддержки limited-use tokens клиентом; не включайте её вслепую.

Не отправляйте пользователям debug APK и не добавляйте debug token в release.
Официальные инструкции:
[App Check для AI Logic](https://firebase.google.com/docs/ai-logic/app-check),
[Play Integrity на Android](https://firebase.google.com/docs/app-check/android/play-integrity-provider),
[контроль квот](https://firebase.google.com/docs/ai-logic/quotas).

Фото, чеки и вся база не отправляются в ИИ. Передаются вопрос, выбранные
характеристики автомобиля, последний фактический пробег и только явно выбранная
краткая сводка. Согласие можно отозвать в настройках. Реальную защиту Firebase-проекта проверяйте в консоли. В просмотренном фрагменте
логов устройства от 2026-10-25 после подключения не было прежней ошибки App Check
403. Предупреждение `Auth not registered, skipping` относится к отсутствующей
необязательной Firebase Authentication, что подтверждено исходником установленного
Firebase AI SDK. Само предупреждение не доказывает успех или сбой генерации.

Новые debug-сборки дополнительно пишут безопасный тег `DriveCareAI`: начало,
использование сохранённого ответа, успешная валидация/сохранение или ошибка. Текст
вопросов, ответов и токены в эти сообщения не добавляются.
